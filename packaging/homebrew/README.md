# Homebrew formula (draft, unpublished)

**There is no Homebrew installation of SigSieve.** `sigsieve.rb` is a draft
kept in this repository for review. It is not in homebrew-core and not in any
tap, and `brew install sigsieve` does not work. Publishing it (in a tap or in
homebrew-core) requires explicit maintainer approval.

SigSieve stays an **experimental, unaudited alpha** whichever way it is
installed. Packaging changes neither of those. Until a formula is published,
use [docs/INSTALL.md](../../docs/INSTALL.md).

## What the draft does

- Builds `v0.1.0-alpha.2` from the GitHub source archive of the immutable tag
  (`refs/tags/v0.1.0-alpha.2`, commit `fc7484be0371242f517b6628b0f7dcc3a9a12a29`)
  with `cargo install --locked` (via Homebrew's `std_cargo_args`).
- Has no `head` block on purpose, because that would build the untagged `main` branch.
- Its `test do` block needs no SSH agent. It checks that `--version` matches the
  formula version, that `doctor` exits 1 with `Upstream agent: FAIL` against a
  missing socket, and that a malformed `--allow-fingerprint` exits 2
  (`Configuration: INVALID`). These exit codes come from `src/cli.rs` and
  `tests/cli.rs`. The block does not exercise filtering.

### Source archive versus release binaries

The formula builds from source, so it works on every platform where
Homebrew's Rust builds the crate. It does **not** install the attested release
binaries. The source archive is generated by GitHub and has **no provenance
attestation**. Its integrity was checked locally only:

| Check (2026-10-29) | Result |
|---|---|
| `sha256` of `archive/refs/tags/v0.1.0-alpha.2.tar.gz` | `a05994e71a165d5b1759c4cad2528aab2a02269bc7db85164359dec4829977a7` |
| Extracted contents vs. `git archive` of tag commit `fc7484b` (`diff -r`) | identical (exit 0) |

These are the attested release binaries, as an alternative. A binary formula
would cover only these targets:

| Target | Archive | SHA-256 |
|---|---|---|
| macOS arm64 | `sigsieve-v0.1.0-alpha.2-aarch64-apple-darwin.tar.gz` | `18ad494d029d9b207074f79778ed49099f8d0114575ad8554d44a9d0ca3c28ec` |
| Linux x86_64 | `sigsieve-v0.1.0-alpha.2-x86_64-unknown-linux-gnu.tar.gz` | `b9dbe8f4d771cd2a054a238af5a7e400f99e8ed5a7977457ee77a06ec79b42c9` |

No binary is published for Intel macOS or Linux arm64, so a binary formula
would have to fall back to source there. Homebrew checks only the `sha256`,
not GitHub provenance. Whoever pins the digest must run the provenance check
first.

### Toolchain

The repository pins Rust 1.99.1 in `rust-toolchain.toml`. Homebrew's `rust`
formula is not rustup and **ignores that file**. It builds with whatever Rust
version Homebrew ships (1.99.1 on 2026-10-29). These versions will drift
apart. A future crate that needs a newer compiler fails to build, and an older
Homebrew Rust has not been tested.

## Updating for a new release

Do every step again for each release. Never reuse a digest or copy one from a
release page without checking it.

1. Use only a published, verified pre-release tag that the release checklist
   accepted ([docs/RELEASE_CHECKLIST.md](../../docs/RELEASE_CHECKLIST.md)).
   Never use `main` or an Actions artifact.
2. Resolve the tag commit:
   `gh api repos/semihbugrasezer/sigsieve/commits/TAG --jq .sha`.
3. Download the release archives into a fresh, empty directory and check them
   against the published checksums and provenance:

   ```sh
   gh release download TAG -R semihbugrasezer/sigsieve -D "$dir"
   cd "$dir"
   shasum -a 256 -c sigsieve-TAG-TARGET.tar.gz.sha256
   gh attestation verify sigsieve-TAG-TARGET.tar.gz \
     --repo semihbugrasezer/sigsieve \
     --signer-workflow semihbugrasezer/sigsieve/.github/workflows/release.yml \
     --source-ref refs/tags/TAG --source-digest COMMIT \
     --deny-self-hosted-runners
   ```

4. Download `https://github.com/semihbugrasezer/sigsieve/archive/refs/tags/TAG.tar.gz`,
   compute `shasum -a 256`, and compare its extracted tree with
   `git archive --prefix=sigsieve-VERSION/ TAG` (`diff -r` must be empty).
5. Update `url`, `sha256` and the commit comment in `sigsieve.rb`, then run
   `ruby -c sigsieve.rb`. Run `brew style` and `brew audit --new` only in a
   tap that a maintainer approved. Homebrew refuses both for a formula file
   outside a tap.
6. Keep the alpha and unaudited wording. Get maintainer approval before
   publishing anything.

## Before publishing: known obstacles

- homebrew-core does not accept alpha/pre-release versions, and its
  notability rules apply. A maintainer-owned tap is the realistic first
  channel, and it needs approval. No tap exists.
- `brew style`, `brew audit --new` and `brew install --build-from-source` plus
  `brew test` have not been run against this draft. Homebrew requires a tap
  for all of them.
